# roam-pele Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Roam Depot extension that draws `{{[[mermaid]]}}`, `{{[[pele]]}}` and Mermaid code blocks with Pele.

**Architecture:** Pure text modules (source assembly, fence parsing, token conversion, host registry) are unit-tested in Node. A thin DOM layer finds Roam's rendered anchors with one debounced `MutationObserver`, inserts extension-owned host elements next to them, reads diagram source through `roamAlphaAPI`, and mounts Pele. CSS (`:has()`) hides Roam's native output only while a working host follows it.

**Tech Stack:** TypeScript 5.9.3 (type-check only), esbuild 0.28.2 (bundle), `pele` 1.6.0, Node 24 `node:test` (native TS type stripping), Roam `extensionAPI` / `roamAlphaAPI`.

**Spec:** `docs/superpowers/specs/2026-10-18-roam-pele-design.md` (read it first; section refs below are `§n` of the spec).

## Global Constraints

- `pele` pinned to exactly `1.6.0` in `package.json` (`"pele": "1.6.0"`). Never `1.0.0` (unrelated package).
- Ship only `extension.js` (single ESM file, `export default { onload, onunload }`), `extension.css`, `README.md`, `CHANGELOG.md`. No code splitting, no runtime network calls, no remote code or CSS.
- `build.sh` = `npm ci` + bundle; must finish well inside Roam Depot's 5-minute CI job.
- Every extension CSS class starts with `roam-pele`.
- Never write to the graph except the two convert commands (Task 9).
- Never change classes or contents of React-owned nodes. Never insert inside `.rm-mermaid > div`, the CodeMirror editor wrapper, `.cm-editor` or `.cm-content`.
- Anchor only on Roam class names and `roamAlphaAPI`; never on minified globals (`$APP`, `shadow$provide`).
- `removePullWatch` is always called with all three arguments.
- Pele `mount` always gets `zoom: false`.
- Live checks only in the throwaway test graph the user names, in the Claude app's built-in browser, signed in by the user. Never sign in, never change account settings. Ask the user before enabling Roam developer mode or loading the extension.
- Commits only when the user has authorized them. Subject: Korean Conventional Commit ending in `-다`, ≤50 chars, no period, then `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work on branch `feat/roam-pele`, not `main`.
- Repository files are written in English.

## Review Focus

1. The same block shown twice (main view + sidebar, or an embed): both diagrams update on edit, and closing one keeps the other's watch alive. → Task 4 registry tests.
2. Roam re-renders (Loading→svg, collapse/expand, entering and leaving edit mode): exactly one host per anchor, never zero or two. → live check in Task 6 step 5.
3. One block holding several fenced code blocks, only some Mermaid: the preview attaches to the right one(s). → Task 3 `fenceBodies` test + live check in Task 8.
4. Empty sources (no children, a child that is only `mermaid`, a code block that is only `mermaid`): no crash; `{{mermaid}}` keeps Roam's help card, `{{pele}}` shows the hint, code block shows nothing. → Task 2 `hasChildren` test + live checks in Tasks 6–8.
5. Unload or developer reload while diagrams are on screen: no `.roam-pele` element, observer or watch left, Roam's native mermaid visible again. → live check in Task 10.

- [ ] **Step 3: Implement `src/source.ts`**

`unwrapFences` uses Roam's own regex, global, and passes each captured body through "drop the first line if its trim is `mermaid`":
`/`````(?:[^\n]*\n)([\s\S]*?)(?:\n?`````)|````(?:[^\n]*\n)([\s\S]*?)(?:\n?````)|```(?:[^\n]*\n)([\s\S]*?)(?:\n?```)/g`.
Builders walk descendants pre-order (root excluded), sorting each level by `:block/order`, map each string (missing → `""`) through `unwrapFences`, and join with `"\n"`; the pele builder prefixes every line of a depth-`d` string with `"  ".repeat(d)`.

- [ ] **Step 4: Implement `src/fences.ts`**

`fenceBodies` uses the same 5/4/3 alternation with the info line kept: `/`````([\s\S]*?)`````|````([\s\S]*?)````|```([\s\S]*?)```/g`. `mermaidSource`: first line trimmed `mermaid` → rest; else second line trimmed `mermaid` → lines after it (`// shortcut: treats any first line as a language line, fine because Roam shows unknown languages as javascript`); else `null`. `docMermaidSource`: first-line rule only.

### Task 4: Host registry

**Files:**
- Create: `src/registry.ts`
- Test: `test/registry.test.ts`

**Interfaces:**
- Produces: `class HostRegistry<H>` with
  - `constructor(watch: (uid: string, onChange: () => void) => () => void)`
  - `add(uid: string, host: H, refresh: (host: H) => void): void`
  - `remove(host: H): void`
  - `hosts(): H[]`
  - `clear(): void`

Semantics: the first `add` for a uid calls `watch` once; its `onChange` calls `refresh` for every host of that uid; removing the last host of a uid calls that uid's unwatch; `clear()` unwatches everything and forgets all hosts. Adding the same host twice is a no-op.

- [ ] **Step 1: Write failing tests** with a fake `watch` that records calls and returns an unwatch spy:
  - two hosts on one uid → `watch` called once; firing `onChange` refreshes both
  - removing one of two → unwatch not called; removing the second → unwatch called once
  - hosts on two uids → two watches; `clear()` → both unwatched, `hosts()` empty
  - `add` of the same host twice → one refresh per change
